# 通知过滤 App · 使用说明

> 适用版本：11.5 ｜ 目标设备：Android 8.0+（`minSdk 26`），在小米 15 / 澎湃 OS3 上开发与验证
> 纯本地运行、不联网、无账号。除「备份到坚果云」外不会发起任何网络请求。

---

## 1. 安装

1. 把 `notification-filter-v11.5-release.apk` 传到手机（微信文件传输 / 数据线均可）。
2. 点击安装。系统会提示「未知来源应用」，允许你用的文件管理器即可（本 App 是侧载，不上架应用商店）。
3. 打开 App，按首页的**权限引导**逐项授权。

> 升级：直接安装新的 APK 覆盖即可，规则 / 黑名单 / 设置 / 流水都会保留（同一个签名密钥）。
> 降级会被系统拒绝——如需回退到旧版本，必须先卸载（会清空数据，请先备份）。

---

## 2. 快速上手（三步）

1. **授予「通知使用权」**（必须）。没有它本 App 收不到任何通知。
2. 首页打开**总开关**，确认状态显示「过滤中」。
3. 规则页点「新建规则」：填关键词 → 选动作 → 保存。

想先看效果：规则编辑页底部有「测试」，用通知栏里现有的通知或历史流水当素材，
能看到「命中 X / 共 Y 条」以及每一条**为什么命中 / 为什么没有命中**。

---

## 3. 规则怎么配

一条规则 = **匹配条件 + 作用范围 + 动作**。

### 3.1 匹配条件

先选「匹配字段」：标题 / 正文 / 消息列表 / 副标题 / 摘要 / 发送者，
还能追加「元信息」（通知 key、tag、渠道 ID 等）以及**任意 extras 字段**。

正在播放的音乐：字段面板里可以直接选 `media.title` / `media.artist` / `media.album` /
`media.package` 等（键名都以 `media.` 开头）。这些值来自当前活跃的 MediaSession，
面板上每个字段后面会显示**现在的实时值**，抓得到再勾。
采集是「按需」的：只有保存过引用 `media.*` 的启用规则时才启动，平时零开销。

再选匹配模式：

| 模式 | 含义 |
| --- | --- |
| 全部内容 | 不看关键词，命中所有通知 |
| 包含任一 | 关键词任一命中 |
| 包含全部 | 关键词全部命中 |
| 不包含任一 | 反向排除 |
| 不包含全部 | 反向排除（全部都不在才算命中） |
| 包含 A 且不含 B | 「要看、但要排掉」的常见用法 |
| 正则 | 写正则表达式，适合复杂格式 |

多个关键词用换行或逗号分隔。

### 3.2 作用范围

- **全局**
- **仅指定 App**
- **全局但排除指定 App**

### 3.3 优先级

规则按列表顺序自上而下，**先命中先处理**（只执行第一条命中的规则）。拖动可调整顺序。
**黑名单优先级最高**，会无条件消除对应 App 的全部通知。

## 4. 六种动作

| 动作 | 说明 |
| --- | --- |
| 消除 | 直接从通知栏撤掉 |
| 推迟 | 撤掉后，到设定时刻重新发回来（可设多个时刻） |
| 替换 | 用自己写的标题 / 正文重新发一条（可保留图标、大图、渠道名） |
| 朗读 | 把通知内容读出来（TTS） |
| 弹幕 | 在屏幕上飘一条弹幕，不撤原通知 |
| 悬浮 | 在屏幕指定位置显示一张卡片，不撤原通知 |

一条规则可以同时配多个动作（例如「消除 + 朗读」），流水里会把执行过的动作全部列出来。
弹幕 / 悬浮 / 替换的文案都能用占位符自由拼装。

---

## 5. 占位符（模板里能写什么）

规则编辑页的「占位符速查」里点一下即可复制。

| 占位符 | 含义 |
| --- | --- |
| `{title}` `{text}` `{app}` | 原标题 / 原正文 / 应用名 |
| `{textLines}` `{subText}` `{summaryText}` `{people}` | 其他文本字段 |
| `{key}` `{id}` `{tag}` `{pkg}` `{channelId}` `{time}` | 通知元信息 |
| `{extras.键名}` | 任意 extras 字段（键名大小写敏感，没有该键出空串） |

两组动态 token（都要先在「内容提取」里配好提取器）：

- `{re1}` ~ `{re9}`：只从**当前这一条**通知里抓，实时、不累积；
- `{items1}` ~ `{items9}`：把**多条**通知的抓取结果攒成列表。

模板整体渲染后会去掉首尾空白；没识别的 `{xxx}` 按空串处理。

## 6. 内容提取（用正则抓内容）

用途：从通知里抓出你关心的片段（取件码、验证码、运单号…），再拼进弹幕 / 悬浮 / 替换文案。

四步：

1. 打开「内容提取与汇总」的总开关；
2. 点「添加提取器」——列表号就是占位符里的 N（第 1 个 → `{re1}`）；
3. 勾选要匹配的字段，填正则（要取的部分用括号），捕获格式填 `$1`，勾「启用」，条数上限 > 0；
4. 回到模板里写 `{re1}` 或 `{items1}`。

正则示例（取 6 位取件码）：

```text
正则：取件码[：:为是]?\s*(\d{6})
捕获格式：$1        （$0 = 整段匹配，$1 = 第 1 个括号里的内容）
```

> ⚠️ 启用 + 正则非空 + 上限 > 0，三者缺一，`{re1}` 就会被判成未识别占位符。

**当场验证**：配好后点「用通知栏第一条通知试提取」，它会直接显示每个 `{reN}`
从真实通知里抓到了什么；没抓到会提示检查中文冒号 / 空格 / 位数。

## 7. 弹幕与悬浮

### 弹幕

- **贯穿式**：从右往左滚动，多条占顶部轨道。只要屏幕上还排得下就继续显示，排满了才排队。
- **定位式**：按九宫格位置出现，停留后消失，多条依次堆叠。
- **样式**：颜色 / 渐变 / 圆角 / 内边距 / 字号 / 透明度 / 出现与消失动画（各自可设时长）。
- **预览**：样式设置页顶部有实时预览；「发射」可让预览里同时出现多条，
  「真机发射」按当前样式真的往屏幕上打一条。

### 悬浮

- 位置用九宫格 + 偏移量精调，可以覆盖到状态栏区域。
- 支持常驻（停留 0 秒）——不会自动消失，需在首页菜单「清除屏幕显示」撤下。
- 打开样式页即把编辑中的样式投到屏幕真实位置，所见即所得。

### 条件显示

「悬浮显示条件」里可设：某 App 有通知、屏幕亮 / 灭、充电中、时段、前台是某个 App 等，
满足才显示、不满足自动消失。

## 8. 需要的权限

| 权限 | 必需性 | 用途 |
| --- | --- | --- |
| 通知使用权 | **必须** | 核心权限，没有它什么都做不了 |
| 悬浮窗权限 | 弹幕 / 悬浮必须 | 否则覆盖层窗口无法显示 |
| 无障碍服务 | 可选 | 只有「按前台 App 显示悬浮」这类条件才需要 |
| 电池优化白名单 | 建议 | 避免后台被系统杀掉 |
| 后台弹出界面 / 后台运行 | 小米机型建议开启 | 否则弹幕可能被拦 |

以上都能在首页的权限引导里逐项检查与跳转。

## 9. 备份与恢复

入口：首页右上角菜单 →「备份与恢复」。

### 备份什么

规则 + 黑名单 + 应用设置（总开关 / 主题 / 深浅模式 / 常驻通知 / 多任务中隐藏）。

### 本地备份

- 「选择文件夹」→ 授权一次，之后一直有效（系统重启也不丢）。
- 「立即备份」→ 在该文件夹里生成 `nf-backup-时间戳.json`，保留多份，不会被自动删。
- 自动备份写固定文件名 `nf-backup-auto.json`，每次覆盖，不会堆一堆文件。

### 坚果云 WebDAV

- 服务器地址默认 `https://dav.jianguoyun.com/dav/`。
- 账号 = 坚果云登录邮箱；密码 = **应用专用密码**
  （网页版 → 账户信息 → 安全选项 → 添加应用密码）。**填登录密码一定认证失败。**
- 「远程目录」默认 `notification-filter/`，只决定放在哪个目录，**文件名按当天时间自动生成**
  （如 `nf-backup-20261018-1605.json`），可保留多份、挑任意一份恢复；目录不存在会自动创建。
- 「测试连接」验证账号密码 + 写权限，并顺带把远程目录建好（已存在则跳过），
  不会上传或删除任何文件。
- 每个备份文件右侧除了「恢复」还有一个删除图标，删本地 / 云端文件都需要二次确认。

### 自动备份

- 开关 + 间隔（每天 / 每 3 天 / 每周）+ 时间点（默认 03:00）+ 目标（本地 / WebDAV / 两者）。
- 云端自动备份同样按时间命名保留多份：只保留最近 30 份，更早的自动删除；
  手动备份的文件和恢复前快照永远不会被自动删。
- 系统可能延迟几分钟触发，属正常（省电策略，不是 bug）。关机重启后会自动重排。

### 恢复

- 两种入口：本地文件列表、云端文件列表，点右侧「恢复」。
- 先弹预览：多少条规则、多少黑名单、哪些设置——确认后才真正写入。
- 规则一律**追加**到现有规则之后，**不会删除你现在已有的规则**；黑名单与设置按备份**覆盖**。
- 「只恢复规则」= 只追加规则，黑名单与设置一律不动。
- 恢复前会自动在备份位置存一份 `nf-before-restore-时间戳.json`（只保留最近 5 份），
  导错了可以用它退回来。

### 关于联网

这是本 App 唯一会联网的功能。不配置 WebDAV、不开启它，就完全不会发起任何网络请求。
WebDAV 密码用系统密钥库（Android Keystore）加密后保存，不是明文。

## 10. 常见问题

**Q：弹幕不出现？**
A：先确认悬浮窗权限；再看规则是否命中（用「测试」验证）；最后检查样式里的透明度是否为 0。

**Q：改了关键词，测试结果没变？**
A：测试面板只统计「当前这一条规则」，且用的是眼前这份草稿（不用先保存）。
结果上方会显示「本次按关键词：xxx」，如果这里没跟着变，说明草稿没构造成功。

**Q：`{re1}` 提示未识别？**
A：去「内容提取」确认：总开关打开、提取器勾了启用、正则非空、条数上限 > 0。

**Q：`{re1}` 渲染出来是空的？**
A：点「用通知栏第一条通知试提取」，看正则到底抓到没有。
最常见原因是中文冒号「：」和英文冒号「:」不一致，或数字位数不对。

**Q：通知被消除了但想找回来？**
A：记录页有完整流水，点进详情可以「恢复通知」。

**Q：记录页里一条通知占了一整屏？**
A：不会。下载 / 备份 / 音乐 / 导航这类通知会原地刷新进度，**同一条通知在流水里只占一行**，
内容随更新刷新、位置不动；等这条通知从通知栏消失后，下一次再来才是新的一行。
统计口径同步为「一条通知计一次」，不按刷新次数累加。

**Q：两套规则都命中同一条通知？**
A：只执行列表里最靠前的那一条。用拖动调整顺序即可。

**Q：记录里一条通知为什么显示好几个效果标签？**
A：因为这条规则同时配了多个动作（比如「消除 + 朗读」）。列表行最多显示 2 个，
多的显示「+N」，进详情看全量；筛选也能按其中任意一个筛出来。
带错误色（红）的标签表示那个动作没做成：朗读跳过 / 替换失败 / 屏幕显示跳过。

**Q：正则里写了 `(?<=…)` / `(?=…)` 断言，但一直不命中？**
A：三个常见原因：
1. **后行断言里不能用无上限量词**：Android 的正则引擎（ICU）要求后行断言长度有上限，
   `(?<=取件码[：:]?\s*)` 这种带 `*` `+` `{n,}` 的写法在电脑上能跑、在手机上编译失败。
   本版已自动等价改写（`(?<=X)P` → `(?:X)P`）并会在「测试」的命中原因里注明；
   更稳的写法是把前面的文字放进捕获组：`取件码[：:]?\s*(\d{6})`，捕获格式填 `$1`。
2. **断言只在一个字段内成立**：引擎是逐字段匹配的，标题里的「取件」和正文里的号码无法被
   一个后行断言串起来。跨字段请拆成两条规则，或把要一起匹配的字段都勾上再写不含断言的模式。
3. **标点全半角混用**：`（` `）` `｛` `｝` `＊` `＋` 这些全角符号不会被当成正则语法，
   保存时会给出提示，换成半角即可（正文里的全角 `：` `，` 属于正常内容，不影响）。

**Q：通知还在通知栏里，内容变了，但列表里一直是旧内容？规则也不跟着跑？**
A：V11.5 已修。旧版为了防刷屏叠了两道闸：① 内容指纹只认「进度」，其它字段变化被当成「没变」；
② 同一通知 1.2 秒内的第二次更新被整条丢弃（连规则都不跑）。所以会出现「只拿到第一次的内容」。
现在：**任意字段变化都算内容变了**，会完整跑一遍（规则匹配 → 内容提取/聚合 → 动作 → 流水），
流水仍然**就地刷新那一行**（不新增行、不跳位置）。防刷屏改由「指纹挡住内容完全相同的重复投递」+
「一条存活通知只占一行」保证。

**Q：推迟的通知到点了没回来？**
A：检查是否授予了精确闹钟权限；小米机型还需允许自启动。

**Q：坚果云连接失败？**
A：按提示对号入座，改完先点「测试连接」再上传：
1. 「认证失败」→ 密码填的大概率是登录密码。坚果云只认**应用专用密码**；
2. 「无法创建远程目录」→ 去坚果云网页版把「远程目录」里写的文件夹先建好，再回来测试；
3. 「无法连接服务器」→ 核对服务器地址是不是 `https://dav.jianguoyun.com/dav/`，并确认手机能上网。

**Q：为什么没有「焦点通知 / 超级岛」相关功能？**
A：澎湃 OS 的焦点通知需要小米公司主体授权（企业开发者邮件申请），个人侧载应用拿不到，
所以本 App 从未实现该能力。

## 11. 数据与卸载

- 所有数据都在本机：`rules` / `notification_records` / `stats_daily` / `blacklist` /
  `aggregation_items` 存 Room 数据库，设置在 DataStore。
- 卸载 App 会一并删除这些数据，**不会**删除你备份到文件夹或坚果云的备份文件。
- 备份文件是纯 JSON，可以直接用文本编辑器查看（结构见 `需求文档.md` 的「备份封套」一节）。
